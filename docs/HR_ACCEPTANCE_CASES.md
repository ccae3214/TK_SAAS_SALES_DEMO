# 會員與仲介後台驗收案例（不含推播）

## 結論與唯一結果

本輪已實際建立獨立 PostgreSQL／app，使用 Chromium 不同角色登入、真實授權 HTTP 與 DB 讀回執行案例；不是只有靜態文件。40 筆結果：29 通過、9 失敗、2 受阻，**完整驗收未通過**。詳細缺陷、執行方式及限制看 [HR_ACCEPTANCE_REPORT](HR_ACCEPTANCE_REPORT.md)；機器證據看 [結果 JSON](review/hr-acceptance-results.json)。

可填寫結果：[HR_ACCEPTANCE_CASES.csv](HR_ACCEPTANCE_CASES.csv)（UTF-8 BOM，Excel 可開）。CSV 是逐筆結果主表，下方是同批案例閱讀版；修改前置／預期須同步兩份，不能刪除失敗或放寬規則讓結果變綠。P0／P1 是執行排序，不另創產品規格或全站發佈門檻。

## 測試模型與範圍

- 既有工作起點不重做；後台就是會員與仲介使用的產品。同一會員同時關聯 A/B/C 不同進度的事務，三方按該事務實際參與者記錄，不簡化成一次只做一件事。
- 雇主、台灣仲介、菲律賓仲介、工作者、訓練中心、未申請及待審會員皆使用虛構資料與分開 session；另有真正不同機構的拒絕存取樣本。
- 每次寫入後從參與者 API／資料庫讀回同一需求、候選、工人或案件 ID；主選工路徑有真實畫面點擊，其餘部分是登入後 HTTP 整合，不冒稱每個分支都經全 UI 點擊。
- 試驗只在已批准的新 DB `tk_saas_acceptance`；不改正式或原 review DB、不重設會員、不刪 volume、不改產品 schema／權限。worker 與第三方 secrets 未啟用；推播、通話及真實 LINE／Google 不在範圍。
- 基底 main `69871560d89af96d60e48b0f6087d46cca3f7887`；網頁已支援 zh/en/tl。先前舊分支只有中英的說明已被本輪實證取代，不把其他分支視為最新版。
- 新 cohort 僅追加，保留舊失敗資料；測試 admin 沿用。狀態通過／失敗／受阻，實際數字以各輪 JSON 為準；受阻不能算通過或刪除。
- 文件初審以目前產品「護照／PSA／LCR 三取二」為準；撤回使用既有事件，不擅自要求新增原因欄位。這兩項是修正最初案例與新版現況不合，不是修改產品規格。
- 語言技術與語意分開驗：AI／回譯不能代替獨立 Filipino 校對或新手任務測試。390px Chromium 不是實體手機。LANG-02／LANG-08 缺獨立人員而受阻，LANG-05 的實機部分仍未驗。
