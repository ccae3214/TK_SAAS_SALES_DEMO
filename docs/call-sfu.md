# 通話自架 SFU（LiveKit）

聊天室通話預設是「每個人彼此直連」（mesh），最多 6 人。啟用自架 SFU 後，每個人只把影像聲音上傳一份給你自己的 LiveKit 伺服器，由它轉送給其他人，**同時通話人數上限提高到 20 人**。

- LiveKit 是開源專案（Apache 2.0），跑在你自己的主機上，影像聲音只經過你的主機。
- 響鈴、來電通知、接聽拒接、麥克風／鏡頭／喇叭狀態仍由原本的信令處理，不受影響。
- 沒設定 `LIVEKIT_*` 時完全維持原本行為（6 人、彼此直連），可以安全地先合併、之後再啟用。

## 啟用步驟

1. 產生密鑰，寫進 `.env`：

   ```
   LIVEKIT_URL=/livekit
   LIVEKIT_API_KEY=hrcall
   LIVEKIT_API_SECRET=<openssl rand -hex 32 的結果>
   ```

2. 路由器與防火牆放行（轉到跑 docker 的這台電腦）：
   - **UDP 7882**：影像聲音（必要）
   - **TCP 7881**：UDP 被擋時的備援

   信令（7880）不用對外開，由 nginx 的 `/livekit/` 轉送，所以走 Cloudflare 沒問題。影像聲音的 UDP **不會**經過 Cloudflare，是瀏覽器直連主機的對外 IP。

3. 啟動：

   ```
   docker-compose --profile sfu up -d
   docker-compose up -d nginx app
   ```

   nginx 設定有更新，需要重新載入（上面第二行會重新建立 nginx 與 app 容器）。

## 怎麼確認有生效

兩個人以上通話後，瀏覽器開發者工具的 Network 會看到連到 `wss://你的網域/livekit/rtc` 的 WebSocket。第 7 位以上的參加者能加入，就代表已經是 SFU 模式。

## 容量與注意事項

- 一個人上傳一份、下載（人數 − 1）份，伺服器出口頻寬是主要瓶頸。20 人視訊大約需要 20 × 19 ×（每路 0.3～1 Mbps）的下行，建議主機上傳頻寬 100 Mbps 以上。
- 超過 6 位參加者時，客戶端自動改收較低畫質，手機才撐得住。
- 通話中途切換設定不會影響進行中的通話：一通電話走哪種模式，由第一個開始通話的人當時的設定決定。
- 停用：清掉 `.env` 的 `LIVEKIT_*` 並重新啟動 app；之後新的通話就回到彼此直連。
